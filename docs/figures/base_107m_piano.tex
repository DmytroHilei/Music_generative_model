\textbf{Why a cascade.} Head $i$ (a dotted box, own weights) reads the trunk state plus the embeddings $E$ of
the values already chosen,\\[2pt]
\hspace*{0.5cm}$z_0 = h_t,\quad z_i = z_{i-1} + E_i(a_i)$,\\[2pt]
so the note's probability follows the chain rule: $p(\Delta t)\,p(\text{pitch}\mid\Delta t)\cdots$. In training $a_i$ is the true
value (teacher forcing), in generation the sampled one. Loss: the sum of the four cross-entropies.};

\textbf{In parallel.} In training every true value is known (teacher forcing), so all $T$ notes of a window pass
the trunk and the four heads at once, in one pass. The loss is the sum of the four cross-entropies, averaged
over the notes.\\[4pt]
\textbf{One note at a time.} Generation reads a MIDI prompt in one pass (prefill: its keys and values fill the cache),
then runs one trunk step per note: the newest note's keys and values are added to the cache, and its attention reads
all earlier ones. On that one row the heads run one after another, each sampling its value before the next head
reads it.};
